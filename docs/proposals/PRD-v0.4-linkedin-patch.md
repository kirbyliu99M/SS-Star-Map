### P-04｜§3.2 非目標：改寫「不爬 LinkedIn」一行

**原文**（第 126 行）：
> - 不匯入通訊錄、不爬 LinkedIn。

**建議新文**：
> - 不匯入通訊錄；不匯入 LinkedIn 的人脈、聯絡人、訊息等含他人資料的檔案（系統會在上傳時主動拒收）；不爬取 LinkedIn，也不使用代爬的第三方資料服務；不用 LinkedIn API 代使用者自動發文。

### P-08｜§9.5 編輯器體驗：履歷 PDF 一鍵初稿改寫為擷取管線

**原文**（第 676 行）：
> - **履歷 PDF 一鍵初稿**：上傳自己的履歷或 LinkedIn 匯出的 PDF，AI 拆成區塊草稿，逐項確認後才寫入；PDF 解析完即刪，不保存。

**建議新文**：
> - **擷取管線（原「履歷 PDF 一鍵初稿」擴充）**：資料來源 → 擷取 → 對應到區塊 → 使用者逐項確認 → 寫入。
>   - **來源**：(A) 使用者自己的履歷 PDF；(B) LinkedIn「Save to PDF」的 PDF（LinkedIn 官方說明此功能僅限桌機，且僅限檔案語言設為英文的會員）；(C) LinkedIn「資料副本」ZIP（見下）。
>   - **資料副本（C）**：在使用者的瀏覽器裡解壓，**只讀白名單**（Profile、Positions、Education、Skills、Certifications、Projects、Languages、Honors、Publications 等本人資料），**其餘檔案（Connections、Contacts、Messages 等）不讀、不上傳**；若整包 ZIP 到達伺服器，一律拒收並刪除。Recommendations Received（推薦人寫的內容）預設不匯入。欄位以官方輸出為準，實際欄位名稱於 S1 spike 確認。
>   - **擷取**：PDF 抽文字層（不支援掃描檔）→ LLM 依區塊 Zod schema 回傳 JSON，伺服器以同一份 Zod 驗證，失敗最多重試一次，仍失敗改顯示純文字讓使用者手動複製；資料副本的結構化欄位以確定性解析為主，只有自由文字才進 LLM。LLM 不得使用任何工具或網路請求，履歷文字一律視為不可信輸入。
>   - **對應**：姓名、標題 → Hero；摘要 → About；經歷、學歷 → Timeline；專案、出版、獎項 → Projects；技能 → **「我可以幫你」的候選草稿**（最多提示 3–5 條，由使用者改寫後才存；【待決】是否新增獨立技能區塊）；「我正在找」不從履歷推導。
>   - **不擷取**：電話、住址、生日、身分證字號、email、履歷上的推薦人聯絡資料。
>   - **確認**：逐項勾選；含他人姓名的句子預設不勾選並標示；寫入的區塊預設可見度「我的圈子」；寫入前可用「以訪客身分預覽」查看。
>   - **本人聲明**：上傳畫面須勾選「這是我自己的檔案」。
>   - **保存**：原檔處理完成立即刪（失敗也刪），排程每小時清掃超過 1 小時的暫存檔；抽出的文字只留在記憶體；草稿 JSON 未確認者最多保留 24 小時；事件紀錄只記次數與成敗，不記內容與檔名。

**原文**（第 680 行）：
> - **代建**：給素材，由圈內志工或我們代建。MVP 用填資料派對實現。

**建議新文**（對應審查 MAJOR-5）：
> - **代建**：給素材，由圈內志工或我們代建。MVP 用填資料派對實現。代建須經**當事人同意**，發布前須由當事人預覽；素材須由當事人親自提供，不得上傳當事人以外任何人的 LinkedIn 檔案或履歷。

### P-11｜§15.5 編輯器：履歷 PDF 一鍵初稿 5 步改為擷取管線

**原文**（第 1151–1156 行）：
> - **履歷 PDF 一鍵初稿**：
>   1. 上傳到私有的 `uploads` bucket（限 PDF、5 MB）。
>   2. Edge Function 抽出文字層（MVP 不支援掃描檔）。
>   3. LLM 依區塊 Zod schema 回傳 JSON 草稿，並被要求略過身分證字號、住址、電話等欄位。
>   4. 使用者逐項勾選後才寫入。
>   5. 原檔與抽出的文字在處理完成後立即刪除。

**建議新文**（保留原 5 步骨架，補強）：
> - **擷取管線**：
>   0. （僅資料副本 ZIP）瀏覽器端解壓；只保留白名單檔；其餘檔案不上傳。
>   1. 上傳到私有的 `uploads` bucket（限 PDF 或白名單 CSV、單檔 5 MB；拒收 ZIP 與黑名單檔名）。
>   2. Edge Function 抽出文字層（MVP 不支援掃描檔）；CSV 以確定性解析。
>   3. LLM 依區塊 Zod schema 回傳 JSON 草稿；略過身分證字號、住址、電話、email、生日；**標記疑似他人姓名**；不給 LLM 任何工具或網路權限。伺服器以同一份 Zod 驗證，失敗重試一次，再失敗改顯示純文字。
>   4. 使用者逐項勾選後才寫入；預設不勾選含他人姓名者；寫入區塊預設可見度「我的圈子」。
>   5. 原檔與抽出的文字在處理完成後立即刪除（失敗也刪）；草稿 JSON 未確認者 24 小時後刪除。
